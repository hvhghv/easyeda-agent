## 二、修复验证（逐条带证据）

### 2.1 P0：`zone-arrange --apply` 串网 —— 修得很好

同一条命令、同一个块组合，两轮对照：

| | 第一轮（修复前） | 第二轮（修复后） |
|---|---|---|
| 电气后果 | `GND` **整网消失**，9 个地脚被灌进 `+3V3`；`LED_CTRL` 塌进 `MCU_IO0` | **零串网**：GND 剩余 6 脚、`+3V3` 全 5 脚原封不动，只是断连 |
| 报告 | 「页面已毁」 | 「恢复段自动重连 **25 成 / 5 个 pin 待手工恢复**」 |
| 可修性 | 只能 `page-delete` 重建 | 照 `REF→期望网` 清单跑 5 条 `autoconnect`，**网表与重排前快照逐网逐脚一致** |

修复后的 `stillBroken` 清单是**可直接执行**的（`LED1:1→LED1_N2 R5:2→LED1_N2 U2:1→GND U2:40→GND U2:41→GND`），
这正是「判据必须给出能执行的下一步」的正确形态。全页恢复段（`moveKernelPinDeficits`）在后续 4 次
`group-move` 里也反复生效，输出 `恢复段全页补连后网表逐引脚一致`。

### 2.2 note `--zone` 三根因

- **A（全名静默落空）**：本轮 7 条说明**全部** `zoneMatched: true`，含全名形式
  `sy8089_buck_3v3(C1)`、`esp32s3_wroom1_module(C4)` 与短名 `U`/`J_USB`。上一轮同样的全名会被静默
  甩到页角 (35,55)。新增的 `zoneMatched` 字段让"有没有命中"变成可观测量。
- **C（说明带自增长）**：放 note 后分区框 `minY` 不再位移，`partitionOverlap` 稳定为 0；
  上一轮同一操作会让框往下长 53（`554→501`）并造成死锁。

### 2.3 删除路径

删除 P3 的 `Q1/Q2/R8/R9` 四件后，`sch group list` 显示 **`g4` 组注册自动消失**——
上一轮这里会留下陈旧组，并在后续 `block-apply` 时"吃掉"复用同位号的新器件（开局 R1 即被吃）。
`group create --block-id/--instance/--roles` 已在 CLI，缺陷 4 的手工恢复路径可用。

## 三、新缺陷（本轮取证）

### 新 1 —— 说明带高度写死 26，多行说明必被挤出框（P1）

**现象**：7 条说明有 **4 条落在自己分区框外**。

| 页 | 说明 | 坐标 | 它的框 | 判定 |
|---|---|---|---|---|
| P1 | SY8089 | (250,445) | {236,502}–{671,754} | ★ 框外 |
| P1 | POWER_IN | (130,220) | {116,234}–{184,370} | ★ 框外 |
| P2 | WROOM | (50,195) | {32,180}–{364,760} | 框内 |
| P2 | BOOT/RESET | (590,355) | {576,328}–{1074,658} | 框内 |
| P2 | LED | (415,775) | {426,530}–{504,772} | ★ 框外（差 3~11） |
| P2 | 自动下载 | (590,315) | {576,328}–{1074,658} | ★ 框外（差 13） |

**根因**：三个框实测 `noteBBox` 高度**全是 26**（常数），而 SKILL 要求「每模块 1~3 行」，
2~3 行说明渲染高约 36~50，**结构上塞不进去** → 落到回退链的"区外走廊"停在框外。

**决定性对照**（同页同区同字号）：单行 `单行测试` → 落点 (250,530) **命中带内**；
同区 3 行说明 → 落点 (250,445) **框外下方**。

**与根因 C 修复的关系（重要）**：这不是 C 修坏了，而是 **C 修好之后这个缺陷才显形**。
修复前框会一路追着 note 长大把它吞进去（代价是自增长 + 死锁）；修复后框只由器件推导，
于是出框的 note **永久留在框外**。C 的修复方向正确，它只是掀开了底下真正的缺陷。

**建议**：`noteBBox` 高度改为**按该区已登记说明的实际渲染高度预留**（`noteSizeOf` 已有），
而不是常数 26；带高不足时优先加高带（框随之上抬），而不是把说明踢到框外。

### 新 2 —— `sch check` 缺「放对没有」类规则

现有交付物判据只有三条**存在性**规则（`internal/app/cmd_sch_marker_geom.go:774-782`）：
`missing-partition` / `missing-note` / `missing-titleblock`。

- ✅ P3 无框 → `missing-partition` **正确报出**（`7 个器件的页没有功能分区框`）
- ❌ P2 两条说明飘在框外 → `sch check` 只报 `missing-titleblock`，**一句都没提**；
  `zone-plan` 的六项 validation 也全 0（它只校验框↔框、框↔图签，不校验 note 归属）

**建议**：补一条 `note-outside-zone` —— 对每条 `--zone` 登记过的说明，判其 bbox 是否被
该区分区框包含；不包含则 WARN，并给出可执行修法（加高说明带 / `sch note --zone X --x --y`）。
**判据纯几何，Go 侧可算，不需要连接器**，可离线单测，与 `sch gate --strict` 天然挂钩。

### 新 3 —— 连接器在长时间负载下退化（本轮头号瓶颈）

两轮成本画像对照，同类操作的失败率与延迟**系统性劣化**：

| 动作 | 第一轮（81 min） | 第二轮（126 min） | 变化 |
|---|---|---|---|
| `document.open` 失败率 | 3/46 = **7%** | 15/37 = **41%** | ×6 |
| `document.open` 均耗时 | 3.00s | **9.61s** | ×3.2 |
| `connect_pin` 失败率 | 18/287 = **6%** | 30/207 = **14%** | ×2.3 |
| `connect_pin` 均耗时 | 2.04s | **5.41s** | ×2.7 |
| `debug.exec_js` 失败率 | 4/187 = **2%** | 21/185 = **11%** | ×5.5 |
| 总失败率 | 0.5% | 1.3% | ×2.6 |

**直接后果**：`zone-draw` 在 P3 上**结构性走不通** —— 它先建框线（一次写），紧接建区名
（第二次写）必然撞上失败并整体回滚，连试 6 次全败，P3 至今没有分区框。

**订正我先前的判断**：我一度说这是「一次成功后必然节流一次」的确定性机制。更准确的表述是
**写操作在持续负载下高概率失败，中间插一次轻读能显著提高成功率但不保证**——
实测 `[U]→OK, [D_ESD / U]→OK, [TESTONLY]→FAIL`（每次前都插了轻读），
而不插轻读时连续 5 次全败。41% 的 `document.open` 失败率支持"退化"而非"确定性节流"。
**内容无关**（`D_ESD / U` 本身完全没问题，我曾误判为内容触发，逐字符测完推翻）。

**建议**：
1. `zone-draw` 的框线+区名创建路径接入 note 已有的 **settle 重试**（当前只有 note 有）；
   更好的是把「一个区的框线+标题」合并成**单次 `exec_js`**，让它要么全成要么全败。
2. daemon 侧加**写操作的自适应退避**：连续失败后自动插入轻读并延迟重试，
   而不是把瞬时失败透传给上层让 agent 自己重试（agent 重试会造重复，见下）。
3. 长会话考虑周期性 `doc reload` 或连接器自愈探测。

### 新 4 —— `group-move` 位移被钳位时静默报绿

请求 `--dy -110`，实际只走了 **-2**（撞图纸下沿被钳位），但输出是
`✓ 平移 0 件 Δ=(0,-2);内核对账绿`，退出码 0。
从退出码和绿勾**看不出"我要的位移没实现"**，必须自己回读 `clusters` 才发现 ERROR 还在。

**建议**：钳位时显式告警并在结构化输出里给 `requestedDelta` vs `appliedDelta`；
被钳位到接近 0 时应视为**未执行**而非成功。

## 六、给下一轮的优先级建议

按「挡住端到端跑通的程度」排，不按缺陷严重度排：

1. **新 3（连接器退化）** —— 它是唯一**阻断交付**的（P3 框画不出来），且会放大其它所有问题：
   假失败诱导 agent 盲重试造重复，是本轮最贵的时间黑洞（`connect_pin` 占机器时间 64%，失败 30 次）。
   最小可行修法：`zone-draw` 接 settle 重试 + 一个区的框线与标题合并成单次 exec_js。
2. **新 1（说明带高度）** —— 它让「交付三件套」在版式上始终不达标，且是纯几何计算，改动面小。
3. **新 2（`note-outside-zone` 规则）** —— 与新 1 配套：先有判据，才不会再靠人眼发现"多余的 note"。
   这条也是本轮**用户先于工具发现问题**的地方 —— 说明这块确实缺机械判据。
4. **新 4（钳位静默）** —— 一行告警的事，但不修会持续误导。

**不要碰**：`zone-arrange --apply` 的串网已修好，别回退；`prim-delete` 逐个删 + 回读的兜底
仍是删除路径最可靠的形态。
