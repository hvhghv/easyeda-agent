# ADR 0003: 原理图布局 = 同一个刚体求解器递归三层(part→group→zone→sheet)

## Status

Accepted. (2026-08-14) — 用户拍板。取代此前「块布局 / 区内重排 / 整页分区」
三套各自为政的实现。

## Context

到 2026-08 为止,原理图自动摆放是**三批瀑布**,每批只能看见前一批的残局:

```
block-apply   → 器件坐标(关系求解器 bslSolveAround)
     ↓ 器件固定,不可回头
autoconnect   → marker 逐个 pin 独立贪心挑 direction×offset
     ↓ 器件 + marker 都固定
zone-draw / note → 区框、注释,**事后独立命令**,捡剩下的空隙
```

症状是**打地鼠**:同一类病(间距、碰撞、对齐、判定口径)在三处各犯一遍,修好一处
另两处不同步。最近一次实证:marker 重叠的根因是「评分器与 `sch check` 用两把尺」
(c43b83e,真机 12→3),而那只是**一层内部**的两把尺;层与层之间还有三把。

用户对此的判断:「你现在是用根本的方案设计的 sch 功能吗?还是只是在调整?」

## Decision

### 1. 运行时只有四层,block 不是层次

```
part  →  group(虚拟组)  →  zone(功能区)  →  sheet(页)
```

**`block` 是「虚拟组的配方」,不是运行时层次**:一份「哪些 part + 它们之间什么
关系」的声明。归组之后它就是个普通虚拟组,上层不需要知道它来自哪个块,也不该有
任何「块专用」的布局路径。

> 用户原话:「我们应该不要过多的理解这个块的概念,blocks 的概念,还是应该拆散了,
> 它其实都是 part 元素构成的。」

### 2. 三层是同一个算法的三次递归

三步的输入输出**完全同构** —— 一组刚体 + 它们之间的关系 + 一个边界 → 每个刚体的位置:

| 层 | items(刚体) | 关系来源 | 边界 |
|---|---|---|---|
| 1 | part | 块配方的 flow/attach/pair + 实测引脚 | 组的可用区 |
| 2 | group | **跨组网数量 + 端口 dir 推导**(见 4) | 区的可用区 |
| 3 | zone | 跨区网 + 页面惯例 | 图纸可用区(减图签) |

因此收敛成**一个函数,调用三次**:

```go
// solveLayer 是全部三层唯一的布局入口。层与层只换 items / rels / bounds。
func solveLayer(items []rigid, rels relations, bounds layoutBBox) []placement
```

**这是本 ADR 的核心决策**。三套代码(`bslSolveAround` / `zone tidy` / `zone-plan`)
各自的间距常量、碰撞判定、对齐逻辑必须收敛到这一个实现;不收敛就还会继续打地鼠。

### 3. 组内相对位置在归组时固化;上层只平移,不重塑

一旦成组,组内相对位置**不再改变**,组对上层就是**刚体**。上层对下层只有一个动作:
**整体平移(+ 必要时整体旋转)**。

**明确否决「软模块」**(为装箱而改变组的长宽比)。理由:VLSI floorplanning 里软模块
成立是因为那是硅面积、形状无所谓;**原理图的组内画法是可读性惯例**(CH340C 就该
USB 在左、串口在右、去耦贴 VCC),为塞进空档把它重排成竖条 = 用可读性换密度,方向
是反的。**组内相对位置是电路语义,不是布局的自由度。**

放不下的正解是**翻页**,不是重塑:功能拆分到其他页正是多页原理图的意义。

### 4. 组间关系可以算,不需要新声明

组与组之间不能只有碰撞(纯碰撞 = 不重叠、填得满、读不懂)。但顺序信息**已经在
数据里**,不必让块作者再声明:

- 两组之间的**跨组网条数** → 决定该多近(强连接的靠拢)
- 端口的 **`dir`(in/out/bidir)** → 决定左右顺序(信号流向)

同理 zone 层。

### 5. marker 在归组前挂上,组的 bbox 天然含 marker

第一步的次序必须是:**放件 → 连线 → 挂 marker → 封组**。

于是组的 bbox **本身就包含** marker 符号、桩线和文字带,上层拿到的刚体尺寸就是
真实占地。**因此不需要单独的 courtyard/通道预留概念** —— 不是估算通道深度,是
放好之后直接量。(曾提议给器件算「四侧引出通道」,按本设计不必要,已弃。)

### 6. 「填满纸张」不是目标

功能区之间的留白是**可读性的组成部分**。标准是「区内紧凑、区间有隔」,不是密度
最大化。

## Consequences

**必须修的断链(实现缺口)**:`block-apply` 完成后**不登记虚拟组** —— 第一步的产物
是一堆散件,第二步 `zone tidy` 手里没有刚体可排。基础设施齐备(group 已持久化在
`~/.easyeda-agent/workflow/<project>.json`,与 zones claims 同一个 store),只差接上。
这是本 ADR 的第一件实现工作。

**保留复用**:关系语义(`flow`/`attach`/`pair`)、实测引脚驱动的两阶段、
`bslReach`/`bslFlowGap` 这类**从数据算间距**的函数、marker 落点评分(含
`predictedMarkerBBox` = 本体 ∪ 文字带的同尺口径)、`layout-lint` / `sch check` 的
真实 bbox 判定门。

**要收敛(不是删除,是并入 `solveLayer`)**:`bslSolveAround`、`zone tidy`、
`zone-plan` 三处各自的间距/碰撞/对齐逻辑。

**沿用的既有定律**(违反即失败,见 [`docs/concepts.md`](../concepts.md) 与仓库记忆):

- 判定与生成必须**同一把尺**(已两次显形:块布局的半宽、marker 的文字带)
- 避让**只沿关系自己的轴**推,另一轴钉死(环形推让会当场破坏 flow 共线 / pair 成对)
- `#64` 硬拒绝(桩线触异网导线 = 静默短路)永不可降级为软惩罚
- 无程序化 undo;SDK 往返贵(关系求解只回读一次锚件)
- y-UP;确定性(同输入同输出,不得依赖随机/时间)

**验收判据(可量化,真机)**:每一期都要能独立验证 —— `sch check` 的
marker-overlap 条数、`sch layout-lint --strict` 的 overlap / out-of-sheet 数、
SDK 往返次数。不接受「看起来更好」。固定用例仍是
[`esp32MiniRequire.md`](../../esp32MiniRequire.md)。
